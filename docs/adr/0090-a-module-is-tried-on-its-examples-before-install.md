# ADR-0090: Try a module on its examples in a sandbox right after the build

- **Status:** Accepted
- **Date:** 2026-11-16
- **Deciders:** Igor Artasevych
- **Spec:** [7.5](../spec.md#75-runner-and-wasm-modules) (R-RUN-9, R-RUN-12, R-RUN-13, R-RUN-16, R-RUN-17, R-RUN-19)
- **Issue:** [#167](https://github.com/igorrius/ganglion/issues/167); design: [module-trial-run-design.md](../plans/module-trial-run-design.md)

## Context

After the agent builds a module (`module.build`, [ADR-0061](0061-local-modules-built-from-source.md))
nothing shows that it does what the owner asked. The build runs only
`cargo build`; the templates' native tests are not run; `Host.Check` runs
the `health` trigger with no input; the install window lists rights, not
behaviour. The owner found this after building a battery alert on
2026-11-11: the first sign that the module worked was a real message.

What a check must respect:

- The model never reads a module's text (R-RUN-13, R-RUN-16): it may learn
  that a run passed, not what it said.
- Nothing of the node may change: cells, state, counts, escalations,
  listeners, messages.
- A module's time comes from the real clock today (`now_ms`, wazero's
  wall and monotonic clocks), so staleness and schedules cannot be tried.
- The install window is one question of at most `tool.MaxQuestionRunes`,
  compared between the ask and the press (`sameWindow`).

## Options

### A. Examples beside the manifest, tried in the build job

An `examples.yaml` beside `manifest.yaml`: examples as steps that set
cells, move virtual time and fire a trigger, with counted expectations
and canned HTTP answers. The build's background job runs the real `.wasm`
on them in a sandbox (fake ports, virtual clock, empty state), stores the
report beside the build, and refuses the plan when the trial fails. The
model reads node words; the owner sees the messages in the install window.

### B. An `examples` section in the manifest

The same, with the examples inside `manifest.yaml`.

### C. A separate `module.trial` tool

The agent calls it after a build; the window shows the last trial.

### D. Run `cargo test` during the build

The templates' native tests on their fake host.

### E. Inputs generated by the node

The current cells and boundary values by type, no file.

## Comparison

| Criterion | A | B | C | D | E |
|---|---|---|---|---|---|
| Tries the real `.wasm` | yes | yes | yes | no, a native build | yes |
| Knows what the module should do | yes, counted expectations | yes | yes | yes | no |
| The manifest stays the contract of rights | yes | no: test data in the contract | yes | yes | yes |
| Model turns | none extra | none extra | one more per build | none | none |
| Window equal at ask and press | yes, stored report | yes | only if not re-run | n/a | no, cells move |
| Network modules | canned answers | canned answers | canned answers | the template's fake | cannot |

## Decision

**A.** The examples are test data, so they stay out of the manifest that
the rights are read from (B). Running in the build job adds no model turn
and fixes the result before the window is asked (C, E). `cargo test`
(D) tries a native build of the logic, not the module that will run; it
can come later.

The parts:

- `examples.yaml`: format, limits and checks in the design note,
  section 3; read from the module's source folder by the build job.
- A new package `modtrial` runs a build on its examples with
  `runner.Load` and its own ports: in-memory state and cells,
  a recording notify port with `per_day` per virtual day, an HTTP
  transport that answers only the example's URLs, fake secrets. None of
  `modhost`'s run accounting is used.
- `runner.Deps.Clock` (nil = the real clock) feeds `now_ms` and the WASI
  clocks, so the virtual time of an example is what the module sees.
- The report is stored as `<Builds>/<sha>.trial.json`. A failed trial
  sets the plan's refusal "the trial run failed", so `module.install`
  refuses; no `examples.yaml` is allowed and said in the window.
- One more run on the node's current cells, read only, for a module with
  a cell trigger and no network: shown to the owner, not judged.
- The model gets counts and step outcomes in node words; the owner gets
  the messages and reported values, escaped and cut, in the window.

## Security

- **Trust boundaries:** the module's code runs in the same wazero sandbox
  and limits as in production, with fewer host functions reaching the
  node: no real cell is written, no message leaves, no real secret or
  network host is reached.
- **What an attacker controls:** the module's code and `examples.yaml`
  (written by the agent, possibly from a tainted session: `module.write`
  then needs a press, R-RUN-17), and the module's output.
- **Abuse cases:**
  - Module text steering the model: the model gets only counts, step
    numbers, failure kinds and the example names, which are source text
    and outside content unless the source is the node's own (R-RUN-17).
  - Exfiltration through canned URLs or secrets: the HTTP transport never
    dials; secrets are the example's fake values; hosts must still be in
    `http.fetch`.
  - A trial that never ends or eats memory: the manifest's timeout and
    memory per call, 60 s for the whole trial, size limits on the file.
  - Real cells read for the "now" run: only `cells.read`, as a live run
    reads them; nothing is written.
  - Window spoofing by message text: messages are escaped and one line,
    as live module messages are; the section is cut before the question's
    limit, so the rights above it are never pushed out.

## Consequences

- A module comes to the window with evidence of what it does, and the
  agent can fix a module that fails its own examples without the owner.
- The agent writes one more file per module, and the skill must teach it.
- A failed trial blocks the install, so a wrong example blocks a right
  module until the agent fixes the example.
- `runner` gains a clock seam; the rest of the node keeps the real clock.

## Revisit when

Examples cannot express what a module does (a multi-module chain, a
module that reacts to its own reports), or `cargo test` turns out to
catch what the trial misses.
